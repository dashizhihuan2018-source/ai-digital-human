# 动作与交互状态

## 片段与运行合同

- 先锁定认可的角色网格、贴图、骨架和站姿。动作改版时逐项核对中性顶点、索引、纹理、蒙皮权重和逆绑定矩阵。面部形变只作用于声明的区域。替换旧动作和表情时，清点导出清单和宿主菜单，防止历史剪辑被默认注册或反复触发。手骨、衣发跟随、接地与分区碰撞见 [情绪动作技能](https://dashizhihuan2018-source.github.io/ai-digital-human/medusa/#skills)。
- 按产品需求定义循环待机、聆听和说话等会话姿态、单次肢体动作、独立短表情。为每个剪辑记录触发入口、是否循环、可打断条件、退回状态和构图。以美杜莎为例，14 个片段由三种常态、七种可轮换动作和四种短表情组成。思考可作为会话状态，由宿主选择对应姿态。
- 以现有交互规则决定优先级。对话状态抢占自动待机动作，单次动作完播返回当时有效的状态。需要随机轮换时可用每轮洗牌，每轮每项一次，避免跨轮接缝连播同项；自动轮换只在窗口可见且宿主允许动态效果时运行。单独验证用户明确触发的动作。隐藏、角色切换、对话结束和恢复时，各查当前动作与过期计时器。
- 播放一个说话姿态、按实际播报振幅开合、对齐真人音节属于不同证据。真人音节未验证时，交接写明实际达到的同步范围。

## 验收

1. Blender 抽样检查接地、动作峰值、近景指节及衣发穿插，并在空场景重导交付 GLB。导出后清点骨骼、剪辑和脸部形变，确认旧版资源按计划退出加载路径。
2. 目标原生入口逐项点播。核对全身和半身首帧与动作构图、切回原角色、动作被会话打断、播完回有效状态。使用探针时钟覆盖自动轮换边界，再在正常前台按实际时钟观察连续轮次。分别记录隔离候选、当前实装和本人验收。
3. 网站若展示同源角色，按实际可公开范围核对 GLB 与动作清单。录屏从待机录过起势、峰值、收势并回待机。不要用网站点播证明 App 的自动轮换或会话状态机已通过。案例回执见 [项目实证](case-evidence.md)。
