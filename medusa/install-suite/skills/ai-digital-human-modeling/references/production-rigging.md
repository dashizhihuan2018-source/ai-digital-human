# 生产骨骼与服装传权

适用：保留静态认可人物，在独立副本重做全身绑定；研究成熟Git项目后落地可编辑、可验证的骨架。以下区分已实跑的官方样例、失败反例和仍需在人物验证的适配方案。

## 不以骨数代替工程成熟度

记录项目作者、固定提交/安装版本、许可证、调用入口和实际运行证据。MPFB与Rigify提供Blender原生人体和模块化生成机制；mGear为Maya工具框架，可研究guide、模块、蒙皮IO思想，不能声称在Blender直接运行。公开框架并不自动等于某3A游戏的可再分发人物工程。素材许可证与代码许可证分开核查。

已有本机样例实际跑通：`HumanService.create_human` → `HumanService.add_builtin_rig(..., 'rigify.human', import_weights=True)` → `RigService.generate_rigify_rig(..., meta_rig_action='keep')`。MPFB包装入口除官方Rigify生成外还会调整子对象绑定；不要只运行裸生成操作并假定衣物自动接好。保留metarig、参数、原生roll、分段DEF/B-Bone、IK/FK及脚掌控制，避免删合骨链后用统一世界roll或自制COPY_TRANSFORMS控制层宣称等价。

样例通过仅指该环境中的官方生成。不能由样例骨数、默认站姿、零中立位移或归一化权重推导当前人物动画通过。

## 从原生人体到换头/焊颈人物

1. 保存完整原生basemesh及其关节helper。Mask求值后的可见皮肤或切颈后的身体通常缺少官方关节定位所需的顶点，不能直接喂入按原索引的rig拟合器。
2. 核验基础拓扑、来源ID与坐标空间；点数相同或名为source_vertex_id都不足够。基础ID、evaluatedID与切割插值来源分开记录。
3. 沿官方关节策略（如CUBE/MEAN/VERTEX）和已知姿态矩阵适配metarig；保持每条骨的局部轴、连接与roll语义。端点`offset`及其相对尺度必须依官方规则进入同一局部姿态运输；遗漏偏移曾让同锚点的脸/鼻/胸辅助骨塌成微米长，中立外观仍几乎不变。已含偏移的rest回退不可二次加偏移。逐骨审查长度、连接及回退列表后重新运行官方生成器，而非拼贴旧失败控制骨。
4. 换头区域不可套用原生脸部权重；已认可脸/旧keys继续冻结。头骨、眼部刚体与窄颈连续过渡分别建立并验收。诊断照片姿态键不映射为jawOpen或头转。
5. 来源ID可能在焊接/重建环重复，不能字典last-wins静默覆盖。记录每组成员、区域、距均值半径与最大两点距离，均值仅消除遍历顺序依赖，不等于恢复精确对应。原生完整网格中的未权重点可能是helper，需按真实可见皮肤分域统计；不得将全网格缺权数量直接当皮肤缺权，也不得因此忽略皮肤漏权。
6. 保留完整权重作为诊断参照；若目标引擎限制四影响，另做裁剪/归一化版本并比较真实姿态误差。高影响原型不称游戏交付通过；反复在每次混合时截四影响会丢失肩部过渡。

## 衣服：域与拓扑优先于全身最近点

失败反例：全身KDTree最近四点混权后，即使所有点权重和为1、影响不超过4，中立态也几乎零误差，抬臂仍会把袖子拉成长条；改成粗略肩袖分段后也可能暴露肩部。原因不是“骨架不够多”，而是服装顶点绑定到了不适合其运动的源域。

- MPFB的mhclo可保存三点对应与插值系数，资产`.mhw`可覆盖通用传权；持久映射与资产专项权重值得复用，不在每帧重新找最近点。
- 作者Mesh Data Transfer的TOPOLOGY模式适用于已证实的同ID；目标顶点组mask只限制目标混合，不等于限制源BVH。袖子mask不能自动阻止胸背串权。
- CharMorph的SubsetGeometry/fitting_subset与fold代理体现限定源域和复合映射；不是自动识别每只袖子的承诺。阅读源码不等于插件已安装或通过本人物测试。

建议路径（必须逐人物实测）：先验人体变形 → 按原衣片/左右袖/环序号定义域 → 在原控制笼修权 → 通过同一细分/厚度栈传播 → 按严格顶点/面顺序对应仅写高密衣权重。翻折袖口的两层共享原袖拓扑，不按折回后的空间距离分别寻找身体。肩袖交界要连续混合，不能硬切域造成裂缝。保留服装原形状、UV、旧键与非变形组。

数量相同、对应坐标误差0只证明传递通道，不证明肩袖权重正确。若拓扑合同不成立，停止并重新映射，不静默退回全身最近点。对实际生成的DEF骨写权重，不向CTRL/ORG/MCH写蒙皮。

## 独立门禁

保存并新进程重开。先查原始几何、全部旧键、UV/材质/图像、曲线及中立求值冻结；材质相对路径应规范化后比较，不能单凭路径字符串误报图像改变。保留metarig时，权重统计只针对人体实际Armature修改器指向的生成rig，不能把未绑定metarig混入统计。

动作至少覆盖双臂45°/90°、前伸与旋转、屈肘、手指、髋膝、脚底固定及转头；关闭IK伸长做接地诊断。身体灰模与完整衣发妆容各自检查，并看连续中间帧。工作rig、四影响导出rig、FBX/GLB重导入及引擎运行分别验收。任何关节塌陷、长条袖、肩部穿衣或脚漂浮都保留PARTIAL/NO-SHIP。

手指测试须至少掌背、侧面和真正掌内侧三个视角；所有段控响应仍可能形成拇指圈握、指尖离掌而非自然拳头。按官方rig类型核对旋转轴和master控制含义，不套用固定欧拉角宣称闭拳。连续往返测试同时记录每帧有限值、实际足底点位移、相邻采样跳变、末帧与复位误差；视频解码和抽帧只支持对应技术项，不能代替完整连续视觉检查或服装碰撞验收。

掌心取景不按相机名称、世界左右或骨局部轴猜测：内侧相机可能拍到另一只手或被身体遮住，局部轴也可能正对指侧。逐张确认实际可见的指腹、掌指连接与拇指根，再给视角语义命名；腕部截取边界和零散可见片不能直接归因于皮肤裂口。

## 手指动态接触与碰撞域

在中立态选真实掌侧指腹面片并保存来源ID；每次姿态更新后，在声明的共同空间重新求值掌面与指面，按面积、距离和相对法线评价，避免最近指帽误取指甲或侧壁。质心积分和阈值近接仍是代理，不是接触力学证明。开放面片的法线投影不是闭合SDF，负值不能单独当实质穿透。

掌面可能含拇指或掌弓权重，优化拇指后必须重算所有手指接触，不能把之前的掌面当静态障碍。碰撞域保守纳入权重过渡边界三角；只选三个顶点都满足语义阈值的面会漏检。记录域覆盖、共享顶点邻面排除规则与非邻三角检查，不能用几个命名指域替代全手审计。

卷指、拇指对掌、最后收紧可分阶段；有证据的局部轨迹余量必须在端点归零，并在双手密采样与复位中验证。采样零碰撞不证明连续时间安全，更不证明自然拳形；圈握仍须明确否决。原作者参考可看[ContactOpt](https://github.com/facebookresearch/ContactOpt)与[manotorch](https://github.com/lixiny/manotorch)，MANO资产另有许可，不把其轴/角先验直接套到Rigify。
